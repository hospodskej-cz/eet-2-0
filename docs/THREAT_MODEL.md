# Model hrozeb

> **English summary.** Threat model of the EET 2.0 gateway, concentrating on `packages/core`
> (protocol, signing, response trust, X.509 reader). It lists the assets (the register's private
> key, correct registration of every sale, trust in the EET confirmation), the trust
> boundaries, the attackers considered, and for each threat the mitigation with its code and
> test, plus the **residual risks we accept**. The most important ones: revocation (CRL/OCSP) of
> the response-signing certificate is not checked; error answers from EET are unsigned and
> protected by TLS only; the production signing profile is an unverified assumption; the local
> clock decides certificate validity. The model is an internal document written with the code
> and has not been reviewed independently (see [AUDIT](AUDIT.md)).

Stav k 28. 10. 2026. Platí pro `packages/core`. Fronta, server, CLI a ingest jsou v matici jen
tam, kde se na jádro napojují; jejich vlastní model hrozeb tu není (viz [AUDIT](AUDIT.md),
„Co nebylo pokryto“).

## 2. Hranice důvěry

```
 integrátor (POS, skript, HTTP klient)
        │  TB1: vstup do API jádra (validace schématem, limity)
        ▼
 ┌─ brána: packages/core ─────────────────────────────────────────┐
 │  loadPkcs12 ── TB3: soubor .p12, heslo (ze souboru/prostředí)    │
 │  createEetTransport.send                                         │
 │     podpis požadavku (CryptoKey, non-extractable)                │
 │     odpověď ◄── TB2: síť, TLS                                    │
 │     ověření podpisu: response-trust.ts, x509.ts, der.ts          │
 └──────────────────────────────────────────────────────────────────┘
        │  TB2: HTTPS na pg.trzbyeet.gov.cz / produkční endpoint z konfigurace
        ▼
   systém EET (GFŘ)              TB5: dodavatelský řetězec
                                     (npm @finitoapp/eet-client, CI, vložené kotvy CA)
```

- **TB1 – volající → jádro.** Volající je důvěryhodný co do záměru, ne co do dat. Data se
  validují (`schema.ts`).
- **TB2 – síť → jádro.** Nejdůležitější hranice. Podepsané je jen potvrzení (`Potvrzeni`).
  Chybové odpovědi, včetně „kód 0“ ověřovacího módu, podepsané nejsou (SPEC_NOTES §7).
- **TB3 – disk/prostředí → proces.** `.p12`, heslo, konfigurace, databáze fronty. Ochranu dává
  provozovatel (práva souborů, secrets).
- **TB5 – dodavatelský řetězec.** [ADR-004](ADR-004-transport-dependency.md).

## 5. Zbytková rizika (přijatá nebo otevřená)

| #   | Riziko                                                                                                                                                                                                                                               | Proč to přijímáme / co by pomohlo                                                                                                                                                                    |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | **Revokace (CRL/OCSP) podpisového certifikátu I.CA se nekontroluje.** Odvolaný, ale ještě platný certifikát GFŘ by ověřil podvržené potvrzení.                                                                                                       | Rozhodnuto v ADR-002 (síťová závislost v cestě každé tržby). Zmírnění: `leafPins`, krátká životnost (roční výměna) a TLS. Přehodnotit po prvním produkčním ověření nebo při nálezu externího auditu. |
| R2  | **Chybové odpovědi nejsou podepsané.** Útočník s možností přerušit TLS (N1) může vyvolat falešné `rejected` (tržba zůstane k ruční kontrole, `needs_attention`) nebo záporné kódy (opakování). Falešné `accepted` ani tiché ztracení tržby nevyrobí. | Vlastnost protokolu (R §3.2). Ochrana je TLS s EV certifikátem serveru. Pomohlo by připnutí TLS certifikátu serveru; nepřipínáme, protože se mění bez ohlášení.                                      |
| R3  | **Produkční podpisový profil je neověřený předpoklad** (stejná CA a subjekt GFŘ jako na PG). Pokud je jiný, všechna produkční potvrzení skončí `uncertain/signature`.                                                                                | Selže bezpečně. Ověří se při první produkční odpovědi (ADR-002).                                                                                                                                     |
| R4  | **Kotva I.CA není kontrolována na platnost** a `isIssuedBy` nehledí na čas vydavatele ani na jeho `keyCertSign`. Důvěra je pin, ne validace cesty.                                                                                                   | Kotvy jsou naše, pinnuté a otestované; expirace I.CA CA je 2032-06-17 (ADR-002).                                                                                                                     |
| R5  | **Lokální hodiny rozhodují o platnosti certifikátů.** Posunutý čas nebo prošlý čas stroje.                                                                                                                                                           | Provozovatel drží NTP. Případně porovnat s hlavičkou `Date` odpovědi (neimplementováno).                                                                                                             |
| R6  | **Paměť procesu není chráněná:** bajty soukromého klíče po importu nejsou nulovány a `Certificate.der/tbs/spki` jsou měnitelné `Uint8Array`. Kdo má zápis do paměti procesu, má vše.                                                                 | Uvnitř procesu není oddělení práv. Rozumná hranice je proces/kontejner.                                                                                                                              |
| R7  | **Duplicitní atributy jména** (dvě `organizationIdentifier`): čtečka vezme poslední. Aby je útočník mohl využít, musel by mu CA vystavit takový certifikát.                                                                                          | Nevyužitelné bez CA. Přísnější čtení by mohlo odmítnout skutečný produkční certifikát; rozhodnout po prvním produkčním vzorku.                                                                       |
| R8  | **Neminimální délky DER (ve skutečnosti BER) čtečka toleruje.** Důvěra se stejně dělá nad původními bajty (podpis, shoda jmen v DER), takže to nic neotevírá.                                                                                        | Přísnější čtení by riskovalo odmítnutí legitimního certifikátu bez bezpečnostního přínosu.                                                                                                           |
| R9  | **Prázdné `leafPins: []` nepinuje nic** (stejně jako vynechané). Volající, který pole sestavuje programově, si nemusí všimnout.                                                                                                                      | Nezměněno kvůli tvaru API (`ResponseTrust`).
